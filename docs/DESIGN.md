# 策划案 · 同题异解 (Duel)

> 一句话：**同一道题、同一份运气，两种智能，两种过程。**

## 0. 为什么做这个

市面上的「人 vs AI」游戏只比结果，过程被藏起来了。
但人对 AI 真正感兴趣的问题不是「谁分高」，而是：

- 我和它**在同一道题**上到底差在哪一步？
- 如果给它**更少的信息/算力**，我还剩多少优势？
- 为什么它这一步要**看五遍**才动，而我看一眼就走？

所以这个产品的第一性设计不是"双屏"，而是**把上下文对齐、把过程外显**。

## 1. 双栏结构

| | 左栏 · 人类席 | 右栏 · Agent 席 |
|---|---|---|
| 输入 | 方向键 / WASD / 触屏 | `g2048` 工具调用 |
| 认知 | 看着棋盘，靠直觉 | `board` / `forecast` / `search` 逐次查询 |
| 过程记录 | `/` 键写一句想法 | 每次工具调用自动留痕 + `note` |
| 独有优势 | 全局直觉、长程规划、创造性 | 算力、零疲劳、可复盘、可被约束 |
| 独有劣势 | 慢、会算错、会手滑 | 只会评估函数里的世界、不会"感觉到危险" |

中栏不是装饰，是**共享上下文面板**：事件流对照表 + 分岔点仪表 + 预报。
它是把「同样」可视化的地方，没有它整个概念就塌了。

## 2. 核心机制：共享事件流

这是整个设计的支点。

```
开局 seed → 预生成一条事件流 [ {值, 目标格} × N ]
                     ↓
        ┌────────────┴────────────┐
     人类席第 k 次落子        Agent 席第 k 次落子
        └──────── 同一个事件 k ┘
```

保证：

1. **同一条流**：两侧拿到的数值分布完全一致（90% 出 2，10% 出 4）
2. **同一次落子**：各自的第 k 次落子消费同一条事件 k
3. **就近落子**：若事件的目标格已被占（因为路走岔了），按 (曼哈顿距离, 稳定散列)
   落到最近的空格 —— 保证"同一个意图"，同时让两边能各自分岔
4. **挑战同步**：洗牌/定点投放等挑战事件，对两侧施加**同一个变换**（同一个置换）

因此两边**难度一致、运气一致**，差异 100% 来自决策。这是所有结论能站住的前提。

> 选 strict / value / none 三档同步强度，就是为了让玩家自己选「公平」的定义：
> 完全共享运气（strict）→ 只共享难度（value）→ 纯经典 2048（none）。

## 2.5 节奏锁（Pace Lock）—— 为什么必须有它

第一版的 bug 是体验层面的：**AI 会在你思考的时候偷偷跑掉 200 步。**
你根本来不及看它走��么，只能看到一屏最终局面。"同题异解"的前提是**同一步一步地分岔**，
否则过程对照根本无从发生。

规则：

```
locked = pace == 'lock' && 人类还在玩 && AI.steps >= 人类.steps
```

- 你走一步 → AI 解锁**恰好一步** → 重新上锁
- **锁的只是「落子」，不锁「思考」**：`board` / `forecast` / `search` / `note` 随时可用

这一点是整个设计里最重要的取舍。如果连思考都锁，AI 变成一个没有过程的机器；
只锁落子，人类就能一边看自己的盘面、一边看右栏实时刷出
「我预判会走 down，因为预报的 2 落在 A4 会堆死左下角」——

**这才是人类想看的"不同"：不是结果不同，是同一时刻它在想什么和我在想什么不同。**

配套的三件事：

1. **拒绝要可见**：AI 抢跑会留下一条橙色 `⛓ 被节奏锁拦住` 记录，而不是静默失败
   （静默失败会让 Agent 陷入重试死循环）
2. **心跳不进留痕**：`turn` 轮询只计数（`stats.polls`），不写过程流，否则 8 次/秒的轮询会刷爆右栏
3. **人类结束后解锁**：你输掉/赢下之后，AI 自由跑完，方便对比终局成绩

## 3. 过程外显

右栏的过程流是**这个游戏真正的商品**，它必须做到可读：

```
#42  search   depth=3 budget=20000       8ms
      [down 4405332] [left 2961929] [right 1699583]
#43  note     空格只剩2，最大值还在角落，先压边
#44  move     down +64 → 128             3ms
```

人类栏用**完全相同的格式**记录自己的思考（note + move + 用了几次查询），
保证对照公平 —— 人类可以说"我一步到位没有查询"，Agent 也可以说"我 5 次调用才动"。

## 4. 胜负与 handicap

最终成绩：`最高方块 + 效率系数（每千分步数）`，并**单列资源账单**：
工具调用次数、累计算力(ms)、思考 token。

handicap 三轴：

| 轴 | 手段 | 考察什么 |
|---|---|---|
| 算力 | 禁用 `search`，只许 `legal_moves` | 启发式 vs 算力 |
| 信息 | 关 `forecast` / 开 `crossSeat` | 不对称信息下的适应 |
| 时间 | 人类每步限时 vs Agent 算力 | 直觉 vs 搜索 |

## 5. 玩法模式（MVP 只做 1，M1+ 补齐）

1. **对局 Duel**：先到 2048 / 限时比最高方块 —— 已实现
2. **同题异解 Fork**：固定起始局面，看谁在第几步分岔 —— 分岔点已实现
3. **镜像 Mirror**：一方走出路径，另一方在同一起点复现 —— 待做（需完整 replay）
4. **教学 Replay**：双轨回放，每步浮出双方当时的理由 —— trace 已有，需时间轴 UI
5. **盲棋 Poker**：双方都看不到自己的方块值，只看到"两张牌" —— 需扩展内核

> 锁步模式的一个副作用：**一局 2048 要人肉打上千步**。所以
> 「AI 代打左栏（演示）」按钮和 `bots/heuristic.js --both` 是一等公民 ——
> 让人先看懂机制，再自己上手。

## 6. 后续可迁移的题型

内核是 `GameModule` 化的，`2048` 只是第一个实例。挑下一个题目的标准是
**"同题异解"最有戏剧性**的：

- **推箱子 Sokoban**：同一张图，人类绕远路 vs Agent 搜最短解；"解的质量"而不是胜负
- **扫雷**：同一份雷位分布，Agent 调 `probe(x,y)` 逐格排除，人类靠记忆
- **24 点 / 数独**：同题不同解，天然适合"解法树"对照
- **狼人杀 / 囚徒困境**：**信息不对称**的最极端形态 —— 同题不同"可见世界"，
  这里的"同样的上下文"要重新定义成"同样的隐藏真相"，是产品真正的第二春

## 7. 成功判据

- 玩家第一次看到右栏过程流时，会说"它为什么要看五遍？"（过程本身有戏）
- 换 seed 重开一局，人类会想"这次我能不能压它一手"（公平感成立）
- 关掉 `search` 后 Agent 明显变菜，人类产生"我也能教它"的冲动（可玩性成立）
